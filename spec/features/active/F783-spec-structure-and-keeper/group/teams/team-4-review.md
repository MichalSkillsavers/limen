# Team 4 · Cold review of the new texts

Verdict: the texts mostly work for a cold reader. The live proof agent followed `templates/keeper.md` without help (`group/qa/run-1.md`). Five findings change what an agent does; fix them before landing. The other findings are wording only.

Scope: every new or changed line that an agent or Adam reads. That is the templates, the help and usage lines, the diagnostics, the land refusal, the keeper packet, the done wake and the docs. Line numbers refer to the branch named in each section. "Status" records what I saw at the time of writing.

## Findings that change behavior

1. **The keeper's own done wake asks for another keeper.** `src/job/wake-text.ts:59-61` (team 3, `9b63e38`). The done wake of a keeper job says: "If it added, moved or changed a ticket, start limen keeper spec/features/active/F002-plant-greeting/ticket.md --job <keeper id> and land the keeper job instead." A keeper always changes a ticket, so a coordinator that obeys starts a keeper for the keeper. Repro: render `completionWake` for job `2026-10-06-f002-spec-keeper-cd6ba589` (`proof.sh wake`). Replacement: when `<jobDir>/role` is `keeper`, use "This is the spec keeper. Land it; it carries the work and the spec fixes."
2. **The command in the worker's done wake does not run as written.** `src/job/wake-text.ts:61` (team 3). The hint takes the path from the task's first `Ticket:` line. A worker that moves its ticket from `planned/` to `active/` makes that path stale. The hint also has no route flags. Copied as written, the command prints "keeper requires --engine --provider --model --thinking; missing --engine". With the flags, it prints "ticket spec/features/planned/F002-plant-greeting/ticket.md is missing at limen/2026-10-06-f002-plant-greeting-37515160 (5fc9afb)". Replacement: let `limen keeper` follow a moved ticket (no file at the tip: use the one `spec/features/**/FNNN-*/ticket.md` at the tip with the same number, and print "ticket moved: OLD -> NEW"). In the hint, write "start `limen keeper <ticket> --job <id> --engine E --provider P --model M --thinking T`".
3. **The keeper packet tells the keeper to start a keeper.** `src/commands/keeper.ts:78-79` (team 3). The "Land check now:" block copies every gate line, and the last one is `fix: limen keeper … --job <worker id> …`. The keeper is a job that can run `limen keeper`. Replacement: leave out the `fix: limen keeper` line in the packet. Keep the error and warning lines.
4. **The refusal names a role that it just refused.** `src/commands/keeper.ts:25` (team 3). A team coordinator runs with `LIMEN_GROUP_ID`, so it is a group member. It gets "group members cannot start a keeper; the team coordinator or the owner-facing lead does". Replacement: "group members cannot start a keeper; the owner-facing lead starts one after it merges the team branches".
5. **The place-id advice fails in a worktree.** `templates/worker.md:17` and `templates/coordinator.md:18` (lead, `2aaf43b`), and `src/picture/tickets.ts:76` (team 2). All three say "limen picture build --json <file>". In a job worktree that command prints "No map yet in <worktree>/.limen/picture" and exits 1, because the map is gitignored. Replacements: worker and coordinator line: "Place ids: the `id:` lines in `$LIMEN_CONTEXT_ROOT/.limen/picture/nodes/*.md`; do not guess (source: …)". Diagnostic: `unknown place id "X"; fix: replace it with the id: of a file in the map's nodes/ folder`.
