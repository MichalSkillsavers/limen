# Team 2 · The from-scratch test set

Draft 1 (12:40). Sections 4 to 8 follow in later commits.

## 1. Verdict from the design side

Draft. Ten scenarios on one throwaway plant plus six unit files guard every seam the brief names. The estimate is about 3,000 lines, not 2,500, and about 3 to 4 minutes on an idle Mac with files run four at a time. The numbers and method are in section 5.

## 2. The shared fixture

One file, `test/plant.ts`, replaces `test/scratch.ts` (195 lines). Estimated size: 260 lines. It gives every scenario five things.

1. **A throwaway plant.** A temp Git repo with one commit, `limen init` run, `.gitignore` for `.limen/`, a committed `spec/features/active/F001-demo/ticket.md`, and a `.limen/picture/nodes/` place file so `ticket check` has ids. Today `scratchRepo` (test/scratch.ts lines 15-24) makes only the repo; each test runs `init` itself (`limen(scratch, "init")` appears in most seam files). `bin/limen-group-fixture.mjs` (73 lines) builds the same kind of plant for a live group proof and calls `initCommand` directly (line 22).
2. **An allowlisted environment.** The fixture builds the child env from nothing: `PATH` (fake bin first), `HOME`, `LIMEN_HOME` (plant parent), `LIMEN_HERDR=0`, `LIMEN_HUNK=0`, `GIT_CONFIG_GLOBAL=/dev/null`. Today `runLimen` starts from `process.env` and deletes a fixed list of 45 names (test/scratch.ts lines 70-115). That list misses `LIMEN_GROUP_ID` and `LIMEN_TEAM_ID`. Checked: inside this group job, `node --test test/keeper-command.test.ts` fails 2/2 with `missing job id in ""`; with `env -u LIMEN_GROUP_ID -u LIMEN_TEAM_ID` it passes 2/2 (12:29, load 89). A denylist breaks every time the product adds a variable.
3. **One fake engine with a script.** One `pi`/`omp` shim on `PATH` (the product finds them through `PATH`; `LIMEN_PI`, `LIMEN_ENGINE`, `LIMEN_OMP` select them). It answers `--version` and `config get` like today's `writeFakePi` (test/scratch.ts lines 168-180). It reads a script from the task text: `commit`, `fail <code>`, `block` (wait for a file the test writes), `say <text>`. It records argv, env keys and task bytes to the job dir. It loads every `--extension <path>` the product passes (src/runtime/wrapper.ts line 93: `steering.ts`, `communication.ts`, and `group-peer.ts` for group members) through a 30-line fake extension API (`on`, `sendUserMessage`), and fires `session_start`, `before_agent_start`, `turn_end`, `session_shutdown`. `test/steer-command.test.ts` lines 13-42 already do this for one test; the fixture makes it the default. Today 27 different fake engines live in `spawn-command.test.ts` alone (`scratchRepo(` count, inventory script).
4. **A webhook sink.** The helper `bin/tony-finish-ping.sh` refuses any URL that is not `https:` (line 66), so a local `http://127.0.0.1` server cannot receive a real ping. The product-offered seam is a fetch preload: `NODE_OPTIONS=--import=<preload>` replaces `globalThis.fetch` and appends each request to a JSON-lines file (test/finish-webhook-helper.test.ts lines 20-52 already do this). The fixture writes `.limen/finish-webhook.env` (found by `finishWebhookEnv`, src/integrations/finish-webhook.ts line 30; overridable with `LIMEN_FINISH_WEBHOOK_ENV`) and the preload. The "sink" is that file.
5. **A fake Herdr, only for the hosted scenario.** `LIMEN_HERDR=<path>` selects the Herdr binary; `0` turns it off (src/integrations/herdr.ts lines 489-491). The fake records calls and runs the pane command as a child process. No real Herdr anywhere.

**Waiting without timers.** A scenario never sleeps. It waits on product events:

- Job end: `limen wait <id>` blocks until a terminal state (src/commands/wait.ts: `fs.watch` on the job dir at line 41, plus a 1-second fallback interval at line 23). One process exit replaces `waitForState`, which polls the state file every 25 ms against a 10-second wall-clock deadline (test/scratch.ts lines 137-151).
- Engine progress: the fake engine writes a marker file; the test waits with `fs.watch` on that file, bounded only by the `node --test` timeout.
- A blocked engine: the fake engine opens a FIFO and blocks on read; the test releases it by writing to the FIFO. No timer on either side.
- Absence ("no second wake"): order it behind a later positive event. Example: job A finishes, then job B finishes; once B's wake arrives, A's wake count must still be 1. The wake hook sweeps every 500 ms (hook/wake.ts line 567) and in time order, so B's wake is a barrier for A.

**Seams that only offer a wall clock today.** Three:

- Detached timeout: `--timeout` is real time. The scenario uses `--timeout 1s` once with a blocked engine. Cost about 1 s.
- Hosted-uncertainty and claim staleness: `HOSTED_UNCERTAINTY_MS` and `CLAIM_STALE_MS` are constants imported by hook/wake.ts (lines 8 and 32), not env overrides. The set tests them as pure decisions with an injected `now` (section 4), not as waits.
- Group launch-lock wait: the fix in `b62b837` removed a 10-second lock deadline; its test holds the lock for 12 s with a Git post-checkout hook (team-3 finding 00000019, `git show b62b837 -- test/group-command.test.ts`). A barrier released early cannot prove the old deadline is gone (team-3 finding 00000020). The set keeps one 12-second hold in S8 until the product takes a lock-clock override. That is a product change, out of scope here.

## 3. Scenario stories

Ten scenarios, one file each, `test/s<N>-<seam>.test.ts`. Line and time estimates are in section 5.

**S1 · Spawn, detached.** Setup: plant with committed F001 ticket. Commands: `limen spawn --detached --label "F001 demo" "commit"`; `limen wait <id>`; `limen jobs <id>`; then four refusals: an uncommitted ticket, `--role coordinator`, `--engine claude`, and `--engine pi` with no `pi` on `PATH`. Checks: worktree at its own path on branch `limen/<id>` from the base commit; `task.md` holds the exact bytes; argv is the omp detached argv; the engine env has no `HERDR_*` or `PI_SESSION_*`; state `done`, result text and one commit in `jobs`; each refusal exits 1 and leaves no job dir and no worktree. Must catch: a job that edits the caller's tree, a ticket missing from the base, a half-made job after a refusal. Replaces: `spawn-command`, `engine` (argv part), `git-status`, `init-command` (plant part), `wait-command`.

**S2 · Spawn, hosted.** Setup: plant, fake Herdr, `HERDR_ENV=1`. Commands: `limen spawn "F001 hosted" "say hi"`; fake engine ends its session; `limen wait`; then a second hosted job with `block`; `limen stop <id>`. Checks: one tab created in the role space, the pane command has no json flag, the task reaches the engine as `@task` not as a shell argument, session end records `done` with the last assistant text; stop records `stopped` once. Must catch: Herdr idle taken as finish, task text in shell argv, a stop that leaves `running`. Replaces: `hosted-spawn` (CLI parts), `hosted-hook`, `open-command`, `stop-command` (hosted parts).

**S3 · Finish and wake.** Setup: plant; the test process loads `hook/wake.ts` with the fake extension API as the coordinator session (`PI_SESSION_ID=coord`). Commands, from that session: spawn four jobs: `commit`, `fail 7`, `block` then `limen stop`, and `block` with `--timeout 1s`. Then a second listener loads `hook/wake.ts` for the same session; then `/limen off`, a fifth job, `/limen on`. Checks: each job gets exactly one wake with label, state (`done`, `failed`, `stopped`, `failed: timed out`), commits and final text; a job with no tools and no commits says it produced nothing; two listeners deliver each wake once; a batched turn confirms every followUp once; the muted wake arrives once after `on`. Must catch: lost wake, duplicate wake (F042 review-1: three injections for two jobs; a live claim stolen after 31 s), a wake before the state file is durable. Replaces: `wake-hook`, `wake-sweep`, `coordinator-wake`, `finalize`, `finish-receipt` (wake parts), `watch-command`.

**S4 · Steering and context injection.** Setup: plant with `spec/vision.md`, `spec/build.md`, `.agents/limen/styleguide.md`, a project `communication.md`. Commands: spawn `block`; `limen steer <id> "one"`; `limen steer <id> "two"`; release; `limen continue <id> "next"`; `limen wait`. Checks: the engine receives "one" then "two" once each as `steer`; `steer` on a finished job exits 1 and writes nothing; `before_agent_start` returns a system prompt with the styleguide, the register, the vision and board pointers, and no board body for a worker; the continuation reuses the session dir, gets `@continue`, links parent and child. Must catch: a lost or doubled steer, missing project guidance, a continuation that starts a fresh session. Replaces: `steer-command`, `steering-hook`, `continue-command`, `communication-hook`, `inherit` (overlay part).

**S5 · Land.** Setup: plant. Commands: job A `commit` then `limen land --yes A` (fast-forward); job B `commit`, move `main`, `limen land --yes B` (merge); refusals: a running job, a job with no commits, a dirty target, a branch whose ticket fails the strict check, `LIMEN_GROUP_ID` set. Checks: `main` holds each candidate; each refusal exits 1, names the reason, and leaves `main` unchanged; the ticket refusal prints the keeper command. Must catch: landing a running or empty job, landing onto a dirty tree, landing a bad ticket. Replaces: `land-command`, `diff-command` (no Herdr part).

**S6 · Spec keeper.** Setup: plant with `done/2026-09/F004-x`, a `limen/f007-y` branch, a job labelled `F009`. Commands: `limen ticket new "x" --touches demo.place`; `limen ticket new "y" --touches nope`; edit a ticket with a bad date and an unknown key; `limen ticket check`; `limen keeper <ticket> --job <id> --engine omp --provider p --model m --thinking high` while the job runs, then when it is done; `limen picture build --strict`. Checks: the new ticket is F010; the unknown place is refused before any file is made; `ticket check` names file, line and fix for each fault; keeper refuses a running job and starts on a new branch at the candidate tip; two builds give identical bytes. Must catch: a reused F number, a silent bad ticket. Replaces: `ticket-command`, `keeper-command`, `ticket-author-command`, `picture-work`, `picture-tick` (start part).

**S7 · Webhooks.** Setup: plant with `.limen/finish-webhook.env` holding two `TARGETS` and an `AUTHOR_TARGETS` map; fetch preload sink. Commands: spawn `commit` and `fail 3`; `limen continue` the first; a second plant with no config spawns one job. Checks: after each terminal state, one request per target, Bearer header, payload kind/plant/id/reason; the failed job with an empty result still sends; the continuation keeps the parent's config path; no secret or URL appears in stdout, stderr or job files; the unconfigured plant sends nothing. Must catch: a ping before durable state, a ping to the wrong target, a leaked secret. Replaces: `finish-webhook`, `lead-step-finish`, `plant-events` (send part).

**S8 · Groups.** Setup: plant with a group packet (brief, two team notes); a lead registration file. Commands: `limen group start --teams 2 --workers-per-team 1`; each team coordinator spawns one worker; a second spawn past the allowance; two spawns at once for the last slot; one spawn while a Git post-checkout hook holds the launch lock for 12 s; `group publish`; `group wait`; `group stop`; `group close`. Checks: one roster; the over-allowance and the losing concurrent spawn are refused with no half member; the held-lock spawn still records membership; each recipient reads a finding once; a worker cannot `land` or `spawn`; close refuses a dirty member. Must catch: duplicate slots, half-claimed members, the old 10-second lock deadline. Replaces: `group-command`, `status-command` (group parts).

**S9 · Sweep, prune and recovery.** Setup: plant. Commands: spawn `block`, `kill -9` its wrapper, `limen jobs`; spawn `commit`, `limen prune`; `limen prune --retire` after landing; 12 processes register and prune the seat registry at once (fork from the test, released by one FIFO write). Checks: the dead job becomes `failed` once and is wake-eligible; prune drops the finished worktree but keeps a running one and one owned by another checkout; retire drops merged jobs only; all 12 registrations survive. Must catch: a live job reaped, a running worktree deleted, a lost registration (F043 review-2: 78 of 80). Replaces: `prune-command`, `reaper`, `recovery`, `sweep-command`, `jobs-command`, `stop-command` (detached parts).

**S10 · GitHub doorbell.** Setup: plant registered with a fake GitHub API through the same fetch preload; an idle fake coordinator. Commands: `limen github poll` with an authorized `@limen` comment, an unauthorized one, a closed issue, and a forged receipt. Checks: one claim and one coordinator prompt for the authorized comment; none for the others; start and terminal replies posted once. Must catch: an outside user starting work. Replaces: `github-doorbell`, `github-issue-body`, `github-doctor`.

Groups (S8) and the doorbell (S10) are seams of their own: each is a trust or concurrency boundary a user feels, and no other scenario reaches it. Sweep, prune and recovery (S9) are one seam: "a dead or finished job is cleaned up, a live one is not". The picture is not a seam: it is a read-only view; one build check rides in S6.
