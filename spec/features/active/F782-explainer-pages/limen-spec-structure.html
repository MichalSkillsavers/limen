How Limen specs are laid out

Limen keeps its plans as plain Markdown files in Git. This page shows where each file lives, who writes it, and how one command turns these files into the live picture page.

Based on the Limen repository on 6 October 2026. Each fact comes from a file in the repository; the file is named beside it. A uncertain label marks a point that the files do not settle.

1. The folders

The spec/ folder holds the plans. Two related places sit outside it. The coloured label names who writes each file.

Today the active lane holds 17 folders. Two of them share one number: F778-coordinator-and-lead-finish-signal and F778-job-done-notifications. Section 5 shows the warning that this causes.

When Adam answers a question, the coordinator deletes needs-adam and its date. When a problem is fixed, it deletes wrong and its date. The pin then leaves the page. Status (active, done, and so on) is never a field: the folder and the board carry it.

3. The architecture map files

The map lives in .limen/picture/, outside Git. A picture job writes it; nobody edits it by hand. Each file is Markdown with front matter, and the file name is the id plus .md.

A fourth folder, features/, holds 15 feature files. Each one lists the modules it touches, for example limen.feature.f743 touches five picture and command modules. When a ticket has no touches of its own, the page uses the map feature with the same number.

status in a map file is ready (true to its sources), partial (true but not complete) or stub (an id kept for later). It says how complete the description is. It is not the work status.

4. From files to the live picture

One command, limen picture build, reads four kinds of file and writes one HTML page. It never calls a model and never uses the network.

Where the page goes. By default the build writes .limen/picture/map.html. The --out option writes it to another path. Adam's copy is ~/Downloads/limen-picture-live.html, the path that the F780 ticket names. uncertain The repository does not record the exact command that wrote that copy.

The board. The build reads only lines of the form - `FNNN-slug` (🟠 ACTIVE): … under NOW, NEXT, PARKED, DROPPED or PROVEN. It never edits the board. The board stays the owner of feature state.

Duplicate numbers. The build reads lanes in the order planned, active, done, dropped. The first folder with a number is the work item. A second folder with the same number stays off the page.

Refresh. limen picture tick starts a picture job only when code changes. A change to spec/ alone never refreshes the map.

source.missing4 today

What it means: a map file cites a file that is not there. Here, the map still points at tickets in active/, but F728, F740 and F741 have moved to done/2026-10/.

What happens: the page still renders. Only the citation is stale.

Fix: the next picture job updates the sources lines. A ticket move alone does not start a refresh, so the warning stays until code changes or someone refreshes the map by hand.

ticket.duplicate-id1 today

What it means: two folders use the same feature number, here F778.

What happens: the first folder (F778-coordinator-and-lead-finish-signal) is on the page. The second (F778-job-done-notifications) is left out.

Fix: the coordinator gives one of them a new, unused number. This is a filing decision.

ticket.no-touches1 today

What it means: an active ticket names no map place. Here it is this page's own ticket: two explainer pages change no code module.

What happens: the work shows on the page, but lights no place.

Fix: none when no place is known. The contract says: leave touches out and accept the warning. Never guess a place.

Errors that would fail --strict

None appeared today. These are the ones a ticket writer is most likely to cause:

ticket.unknown-touch

A touches id is not a place in nodes/. The build does not invent a link. Fix the id, or remove it.

ticket.bad-field

An unknown key, a date that is not real, needs-adam without needs-adam-on (or the reverse), a request on more than one line, touches: [a, b] instead of a block list, or landed outside done/. The message names the ticket path and line.

Map files have their own errors, for example edge.dangling (an edge points at a place that does not exist) and node.duplicate-id (two files claim one id). The picture job fixes those before it finishes.
